# 模擬與除錯（P3）

IDE 用核心的模擬器（`docs/SIM.md`）執行你正在編輯的程式。模擬器放在獨立的工作緒（`SimSession`），介面永遠只看到狀態快照，
長時間執行不會卡住視窗，隨時可以暫停。

## 基本流程

1. 編輯並建置（自動）。有錯誤的程式不能除錯。
2. 在行號左邊點一下設中斷點（或 F9）。沒有程式碼的行會移到下一個有程式碼的行。
3. **F5** 開始：IDE 先建置目前的文字（含未存檔的），再啟動模擬器並執行，停在中斷點，編輯器自動跳到那一行。
4. 單步、看狀態、改記憶體或 CSR、再繼續。

| 動作 | 快捷鍵 | 說明 |
|---|---|---|
| 開始／繼續 | F5 | 兩個 domain 一起執行 |
| 暫停 | F6 | 任何時候都能中斷，包括無限迴圈 |
| 停止 | Shift+F5 | |
| 重新開始 | Ctrl+Shift+F5 | 重新建置並回到電源開啟狀態（中斷點保留） |
| 單步進入／跳過／跳出 | F11 / F10 / Shift+F11 | 作用於「單步焦點」選定的 sequencer（Debug 選單：Main 或 Peri） |
| 執行到游標 | Ctrl+F10 | |
| 切換中斷點 | F9 | |
| 執行 N 個週期、執行到運算式成立 | Debug 選單 | 例如 `csr[0x120] == 5` |

單步以**來源行**為單位：`CALL` 是一步，進入程序後才逐行；inline 與 softret 兩種呼叫模型行為相同。

## 編輯器裡看到的

- 邊欄紅點：中斷點（空心＝停用或這一行沒有程式碼）。黃色箭頭與底色＝Main 將執行的行，青色＝Peri。
- 一行對應多個位址時（inline 展開的程序行）全部都會設中斷點，命中次數加總。
- `CALL` 那一行也可以設中斷點；命中時顯示的是你設的那一行。
- 增減行時中斷點跟著文字移動；中斷點（含條件）與監看運算式依專案存在設定檔。
- 程式碼在除錯期間被修改：狀態列顯示「source changed: restart to apply」，需重新開始才會套用。

## 面板（View 選單）

| 面板 | 內容 |
|---|---|
| State | 週期、兩個 pc 與所在行、ALU、結果槽、fault（附「Clear fault」） |
| Memory | scratch、csrbuf、slot、meta、rx、常數池、ALU 暫存器；變動的位元組標紅；可直接改十六進位值（可寫的區域） |
| Signals | 模擬器的所有訊號（含 `slot.valid`…）；可改值 |
| CSRs | 程式 `.csr` 命名的 CSR；改值＝寫該 CSR（可能觸發它的動作） |
| Watch | 運算式清單（十進位與十六進位）；空白列新增、清空文字刪除 |
| Call Stack | 兩個 domain：目前位置、呼叫鏈；雙擊跳到呼叫處 |
| Breakpoints | 啟用、條件、命中次數；資料中斷點（值改變就停：`scratch[8..9]`、`csr 0x120`、`signal x` 或任一運算式） |
| Events | 指令、匯流排、CSR、發佈與消耗、fault…可篩選、點一下跳到原始碼；可存成文字、CSV 或 VCD |

## 環境檔

專案的 `environment` 設定指向模擬器環境檔（CSR 種類、I2C 裝置、時序、注入事件，格式見 `docs/SIM.md`）。Debug 選單「Edit Environment File…」
開啟或建立它；它以純文字編輯，未存檔的內容也會被用來啟動。環境檔有錯誤時，開始除錯會列出每一條錯誤。

## 防止失控

每次執行都有週期與牆上時間上限（預設 5000 萬週期、15 秒），到了就停下並說明原因；暫停永遠有效。
中斷點條件、監看運算式寫錯只會顯示錯誤訊息，不會影響執行。

## 目前的限制

- 環境檔只有文字編輯，沒有表單模式與即時驗證（E1 部分）。
- 事件中斷點（NACK、overrun 發生時停止）尚未做；fault 一律停止。
- 回溯（`rewindTo`）服務層已有，介面尚未提供；時間軸、剖析與覆蓋率屬於 P4。
- 行位移追蹤用「游標所在行」推算，大範圍貼上或取代可能讓中斷點位置不準，重新開始會依目前原始碼重新對應。
