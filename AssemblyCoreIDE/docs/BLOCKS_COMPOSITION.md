# 積木的組合方式：上下（流程）與左右（元件）　— v2（依使用者 2026-10-22 的回覆修訂）

> 狀態：**已確認，實作中（M2b，先於 M3）**。對應規格：`docs/ASM_SYNTAX.md`。
> 使用者的決定：①指令之間只有上下，但**一條指令本身可以拆成積木元件**；②**數字就是積木**，有屬性（int／float／double、signed／unsigned、位元寬、const…）；
> ③插入已佔用的插槽時，**原積木彈出成漂浮**；④**舊檔／舊版 IDE 必須都能用**（不接受不相容的升級）；⑤先做 M2b 再做 M3。

> **逐指令的拆解分析、規則與相關性見 `BLOCKS_INSTRUCTION_ANALYSIS.md`（本文件的型別與規則由它導出；與本文件不一致處以該文件為準）**。
> 主要修訂：①區域型別改成精確的 `region:<ID>`（方向由插槽的接受清單表達）；②「長度＋指標」改為插入**區域範圍**窗口、由它推導（`ptr+len ≤ 32` 自動成立）；③`alu` 依運算動態顯示插槽（不可能表達 W410／E203）；④拆解只存在 `parts`，陳述積木的 `type` 與文字欄位不變（相容）；⑤不需要 H7e（區域積木本身標示 domain，沿用 H1）；⑥實作分三期（分析文件第 8 節）。

## 1. 為什麼原本只有上下

Level 1 積木一指令一積木，運算元只是積木裡的文字欄位。模型與引擎早已支援左右組合（值插槽），只是沒有內建積木使用。現在改成：

**指令 = 指令頭（固定的操作）＋元件（插槽）。** 指令之間只有上下（序列器一步一條微指令）；指令的**每個有意義的部分都是元件插槽**，元件本身也能再由元件組成。

| 方向 | 語意 | 連接點 | 外形 |
|---|---|---|---|
| 上下 | 執行順序；`proc` 的 C 形槽＝程序本體 | 上凹下凸 | 方塊 |
| 左右 | 「這個部分是什麼」——元件插進插槽 | 左側插頭 ↔ 右側插槽 | 膠囊；**形狀依型別不同** |

## 2. 元件的種類（每個部分都能是元件）

| 元件 | 型別 | 例 | 用在 |
|---|---|---|---|
| **數字** | `int`（也能直接當 MOV 的來源＝常數） | `5`、`0x20`、`u16 300` | 偏移、長度、指標、常數值 |
| **區域** | `region.r`／`region.w`／`region.rw` | `MAIN_SCRATCHPAD[0..1]`、`ALU_OPA`、`ALU_OUT` | `mov` 的 from／to |
| **運算** | `int` | `a + b`、`a << 3` | 任何 `int` 插槽 |
| **選項元件** | `op.alu`、`sign`、`cond.main`、`cond.peri`、`label`… | `ADD`、`unsigned`、`ALWAYS`、`start` | `alu`、`br_cond`、`jmp`… 的對應插槽 |

選項元件讓「ALU 運算是 ADD」、「簽號是 unsigned」、「條件是 ALWAYS」也是可獨立拖動、複製、重複使用的積木；插槽空著時顯示**行內下拉**（和現在的下拉相同，打字／選擇即可，不必先拖元件）。

## 3. 數字積木（有屬性）

| 屬性 | 值 | 說明 |
|---|---|---|
| 值 | 十進位／`0x`／`0b`／`'A'`／名稱（`.equ`）／浮點 | 欄位直接輸入 |
| 種類 `kind` | `int`（預設）、`float`、`double` | 浮點由產生器換成 IEEE-754 位元組，**組譯器本身只有整數** |
| 正負 `sign` | `auto`（預設）、`signed`、`unsigned` | 範圍檢查依此 |
| 寬度 `width` | `auto`（預設）、`8`、`16`、`24`、`32`、`64` | 位元寬；換算成位元組數＝`CONST` 的寬度 |
| 常數 `const` | 旗標 | 明示放進常數池（`CONST(值, 位元組數)`）|

**用在哪裡就產生什麼**（同一個積木，產生的文字依插槽決定）：
- 插進 `int` 插槽（偏移、長度、指標、ALU 位移量）→ 純數字 `5`；
- 插進 `mov.from`（來源）→ 常數 `CONST(5, 2)`，位元組數＝`width`（`auto` 時＝目的長度，與組譯器一致）。

**依 ISA 實際能力的限制**（組譯器 `CONST` 寬度 1…4 位元組，數值以 64 位元整數運算，無浮點）：
| 屬性 | M2b | 說明 |
|---|---|---|
| 8／16／24／32 位元整數（signed／unsigned） | ✔ | 範圍檢查：8 位元 unsigned 只能 0…255 等；超出 → 積木上錯誤徽章，與組譯器 E201 同一規則 |
| `float`（32 位元） | ✔ | 例 `3.14` → IEEE-754 單精度 → `CONST(0x4048F5C3, 4)` |
| 64 位元整數、`double` | ✘（先報告原因） | 8 位元組放不進單一 `CONST`（上限 4）；顯示斜紋與「CONST 最多 4 位元組，64 位元要拆成兩次搬移（之後的高階積木做）」。**不是永遠不支援**：B4 的多段常數積木會自動拆成多條 `MOV` |

## 4. 值積木目錄

**區域**（由 `isa::kRegions` 產生，不手抄；讀寫權限、大小取自同一張表）
| 積木 | 型別 | 插槽 | 產生 |
|---|---|---|---|
| `scratchpad` | rw | first、last（`int`） | `MAIN_SCRATCHPAD[first..last]` |
| `CSR buffer` | r | first、last | `MAIN_CSR_DATA_BUF[..]` |
| `result slot` | r（Peri 區域） | first、last | `PERI_RESULT_SLOT[..]` |
| `ALU A`／`ALU B` | w | — | `ALU_OPA`／`ALU_OPB` |
| `ALU out`／`ALU status` | r | — | `ALU_OUT`／`ALU_STATUS` |
| `const pool item` | r | 名稱 | `MAIN_CONST_POOL[@name]` |

**運算**（`int`）：`+ − × ÷ & | ^ << >>`、括號；各以兩個 `int` 插槽。**名稱**：下拉列出 `.equ`／`.const`／CSR 名。

## 5. 指令的插槽

| 指令 | 元件插槽 |
|---|---|
| `mov` | from（`region.r` 或數字＝常數）、to（`region.w`） |
| `alu` | operation（`op.alu`）、sign（`sign`）、shift（`int`，僅 SHL／SHR） |
| `csr_write8/set8/clr8` | csr（名稱或 `int`）、value（`int`） |
| `csr_write_sp` | csr、len、ptr（`int`） |
| `csr_read8/read_buf` | csr、len |
| `br_cond` | condition（`cond.main`）、target（`label`）、safe（旗標） |
| `jmp`／`call` | target（`label`）、safe |
| `xfer`／`pub`（Peri） | 依其運算元 |

## 6. 能不能接——逐對的 Assembly 語意規則

吸附只在**兩兩符合**時成立；不符顯示斜紋並說明原因。

| 規則 | 等級 | 內容 |
|---|---|---|
| H7a 型別 | 硬 | `int` 進 `int` 插槽；`region.r` 只進來源插槽；`region.w` 只進目的插槽；`region.rw` 兩者皆可；選項元件進同名選項插槽；**數字也可進來源插槽（＝常數）** |
| H7b 讀寫權限 | 硬 | 例：`ALU out` 不能當目的；`ALU A` 不能當來源；`CSR buffer` 在 `mov` 只能當來源 |
| H7c 常數來源 | 硬 | 常數（數字／`const pool item`）當來源時，**目的必須是暫存區**（不可直接進 ALU、不可進 CSR 緩衝）；插第二個插槽時檢查 |
| H7d 範圍與寬度 | 硬／軟 | 兩端是數字時：`first ≤ last`、不超出區域大小（取自表）；常數值要放得進寬度與正負（E201）；含名稱／運算的在組譯時檢查（顯示警告） |
| H7f 佔用 | — | **插進已佔用的插槽 → 原積木彈出成漂浮積木**（不丟資料；可復原） |
| H7g 不支援 | 硬 | 64 位元／double 在需要 `CONST` 的位置（第 3 節） |

不完整的指令（必填插槽空著且行內欄位也空）：錯誤徽章「`to` 還沒有運算元」；產生文字輸出為註解 `; (incomplete) MOV … -> ?`。

## 7. 與文字互轉，以及「舊檔與舊版 IDE 都能用」

**為什麼我原本說舊版 IDE 會開不了**：原本的想法是檔案格式升級（把運算元的文字改存成結構），舊版看不懂新格式。這是**我的設計選擇，不是必然**——改成下面的做法就不需要升級：

1. **文字永遠保留**：每個運算元仍存成原來的文字欄位（`fields`，例如 `"src": "CONST(5, 2)"`），這是**相容層**，也是單一真實來源的文字形態。
2. **結構是附加的**：元件積木存在新增的選用鍵 `values` 裡（格式版本仍是 1，只增加鍵）。舊版 IDE 讀到時不認得就**忽略結構、照文字欄位產生**——結果相同。
3. **讀入時以文字為準來驗證**：若 `values` 產生的文字＝`fields` 的文字，就採用結構；不同（例如舊版 IDE 改了文字欄位）→ **丟掉結構、由文字重新拆解**。所以兩個版本交替編輯同一個檔不會壞。
4. **舊檔（只有文字）**：開啟時在記憶體中拆解成元件；**存檔時才會多寫 `values`，不改動其他任何東西**；不想要結構的人把檔案用舊版開存即可回到純文字。
5. **匯入文字**：運算元用 parser 拆成元件；**拆不開的不失敗**：保留成「原文」元件（型別 `any`、等寬字、保留原字串），與 `raw` 同一精神。
6. 保證不變：`assemble(generate(import(t)))` 位元組與原文字相同（B0 的測試延伸到全部範例與 fuzz）；另加**相容測試**：新檔交給「沒有插槽定義的舊登錄表」讀寫，文字結果必須相同。

## 8. 畫面與操作（M3 接手）

形狀依型別不同，不合的形狀放不進去；拖近插槽時：能接→插槽亮起；不能接→斜紋＋原因；放在空白處→漂浮積木。插槽裡的積木拖出來即脫離。

## 9. 實作項目（M2b）

| ID | 工作項目 |
|---|---|
| B1-17a | 值型別表（區域讀寫／大小由 `isa::kRegions` 產生）、數字屬性模型 |
| B1-17b | 值積木、選項元件、插槽版指令定義（`mov`、`alu`、`csr_*`、`br_cond`、`jmp`、`call`、`xfer`、`pub`）；每個插槽附帶「文字欄位」作為相容鏡像 |
| B1-17c | 運算元／運算式 parser（匯入）；產生器（含「依插槽決定輸出」、浮點→IEEE-754）；鏡像同步；讀入時的一致性驗證（第 7 節 3） |
| B1-17d | 規則 H7a–H7g（`checkSocket` 擴充＋兩插槽的指令層檢查）、`plugValue` 彈出（H7f）；測試：逐對表、fuzz |
| B1-17e | 版面／繪製：型別形狀、數字屬性標示（如 `u16`）、行內欄位、不完整徽章 |
| B1-17f | 回歸：全範例 import→generate→assemble 位元組相同；舊登錄表相容測試；`asmblk` 顯示結構 |
