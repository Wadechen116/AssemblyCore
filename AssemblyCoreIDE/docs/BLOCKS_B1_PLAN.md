# B1 工作項目：原生 Qt 積木畫布（第 2 版，待確認）

> **第 2 版（2026-10-21）**：依你對 D1 的指示改為**自由擺放**——積木堆疊可放在畫布任意位置、可從任意位置開始嵌套；能不能吸附由「兩兩積木是否符合 Assembly 語意」決定；不能嵌套的以**斜紋底色**示意。受影響的項目都已更新（見 §1b 規則、B1-08、B1-09、B1-22、B1-26 …）。

承接 B0（模型、定義、`.acblk`、Level 1 產生器、匯入器，見 `docs/BLOCKS.md`）。B1 的目標：**在 IDE 裡用滑鼠與鍵盤編輯積木程式，並且立刻看到、組譯、除錯它產生的文字。**
已決定：原生 Qt（`QGraphicsScene`）、每個檔案只有一個事實來源、先 B0～B2 再 B5、高階積木為主（B4）。

## 0. B1 的範圍

**做**：Level 1 積木的圖形編輯器（**自由擺放的畫布**、依語意規則吸附、拖放、欄位編輯、工具箱、Typeblock、復原、剪貼簿）、與工作區／專案／建置／除錯的整合、唯讀的產生碼面板、積木上的基本錯誤標記、繁體中文。
**為 B4 預留但 B1 不做高階積木**：畫布一開始就支援「容器積木」（C 形槽，如 `proc`）與「值插槽」（積木插進積木的欄位，B4 的運算式要用），用測試專用的積木定義驗證，B4 只需要加定義與降階程式碼，不必動畫布。
**不做（留給之後）**：高階積木與變數（B4）、硬體元件抽屜（B2）、資源計量／執行位置／積木上的中斷點（B3）、小地圖、背包、工作區內搜尋、積木層級的重新命名、文字⇄積木即時雙向同步、匯出 PNG。

**驗收**：(1) 只用 UI 操作（腳本化測試）重做 `01_hello_csr`，產生的文字組譯出的映像與原程式位元組相同；(2) `examples/` 與 `sample/` 每個程式都能以積木開啟、不改任何東西存檔後文字不變；(3) 在 IDE 裡 F5 可以除錯積木產生的程式；(4) 全部自動測試通過、Windows 版零警告。

## 1b. 吸附的語意規則（草案，請確認）

連接點有四種：**下接**（上一個積木的下方→下一個積木的上方）、**放進槽**（容器積木的 `BODY`）、**堆疊首尾互接**（把整串接在另一串的尾端或前端）、**值插槽**（B4 的運算式）。規則是純函式 `canConnect(前一個, 後一個, 脈絡)`，回傳「可接／可接但警告／不可接＋原因」；整串互接時檢查接點兩端與整串的 domain。

**硬規則（不可接，顯示斜紋＋原因）**

| # | 規則 | 為什麼（組譯器怎麼說） | 例 |
|---|---|---|---|
| H1 | **domain 相容**：同一個堆疊裡 Main 專用積木（`mov`、`alu`、`csr_read8`、`csr_write_sp`、`csr_read_buf`、`br_cond`、`cascade_*`、`wcet`）與 Peri 專用積木（`xfer`、`pub`、`br_peri`）不能出現在一起；有帽子的堆疊以帽子的 domain 為準，漂浮堆疊以已有積木的 domain 為準（雙方都不專用時不限） | Main 與 Peri 是兩個定序器（E307） | `xfer` 接在 `mov` 之後 ✖ |
| H2 | **帽子只能在最上面**：`.main`／`.peri`／定義區的帽子上方不能接任何東西，也不能放進槽或接在別的積木下面 | 一個區段由 `.main`／`.peri` 開頭 | 把帽子拖到積木下面 ✖ |
| H3 | **`proc` 不巢狀**：`proc` 的 `BODY` 槽不接受 `proc`；帽子不能放進槽 | E105 / E305 | `proc` 拖進 `proc` ✖ |
| H4 | **`ret` 只屬於程序**：`ret` 不能接在「帶帽子的程式流程」上（不在 `proc` 內）；漂浮堆疊上先允許（之後可放進 `proc`） | RET 只在 `.proc` 內有意義 | 主流程接 `ret` ✖ |
| H5 | **`vector` 屬於程式流程**：不能放進 `proc` 的 `BODY` | E315：向量必須指向本 domain 的流程標籤，不能在程序內 | `vector` 拖進 `proc` ✖ |
| H6 | **定義區只放定義與文字**：定義區帽子下只接 `directive`／`comment`／`blank`／`raw`，不接指令積木 | 指令必須在 `.main`／`.peri` 之後（E105） | `mov` 接在定義帽子下 ✖ |
| H7 | **值插槽型別**（B4）：插頭與插座型別不符不可接（以 B1-06 的測試專用定義驗證） | 型別規則 | 比較結果插進數值插槽 ✖ |

**軟規則（可接，積木上標 ⚠，不擋；嚴格模式 D9-b 才擋）**

| # | 規則 | 說明 |
|---|---|---|
| S1 | 無條件跳躍／`ret`／`br_eret` 之後接的不是標籤（可能永遠執行不到，W402） | 常是使用者正要在中間插入 |
| S2 | `br_eret` 出現在主流程（不在事件處理流程，E315） | 是流程性質，由組譯器判斷 |
| S3 | 標籤重複、目標標籤不存在、`cascade_end` 沒有對應的 `begin`、資料流警告（W5xx） | 由組譯器診斷經 B1-47 顯示在積木上 |
| S4 | `raw` 積木：與任何積木都可接（內容未知） | 不擋 |

> 還有你想擋的組合嗎？例如「`alu` 之前沒有任何載入 `ALU_OPA`/`ALU_OPB` 的 `mov`」其實是資料流（W501），我放在 S3；如果你要它變成吸附條件，請告訴我（要走資料流分析，成本較高，建議留給 B3）。

## 5. 風險與對策

| 風險 | 對策 |
|---|---|
| 拖放手感難調（XL 項目；自由擺放接點多、誤吸附風險高） | 吸附半徑可調、只計算滑鼠附近的接點、一次只預覽最近的相容接點；邏輯（找插入點、規則檢查）放在無 Qt 的核心並單獨測試；畫布只負責畫與傳事件；先做「點選目標位置」的備援流程（選積木→Typeblock 插入），拖放壞了也不影響編輯 |
| 浮動編輯器的焦點與輸入法（繁體中文輸入） | 用標準 `QLineEdit`／`QComboBox` 浮在視圖上；專案已經有 CJK 欄位的測試做法；在 Windows 實測 |
| 大檔效能 | 版面引擎純計算、增量重排（只重排受影響的欄）；§B1-53 的門檻在 CI 守住 |
| 為 B4 預留的值插槽沒被用到而腐壞 | B1-06 與測試專用定義＋畫布測試涵蓋（插入、拔出、型別拒絕），不是只寫不用 |
| 文字與積木不同步 | 單一事實來源（`.acblk`）、產生檔唯讀並明說；轉換時保留原檔名（D4） |

| 自由擺放讓「哪些積木算程式」不明顯 | 帽子標示、漂浮堆疊虛線＋「不屬於程式」標籤、狀態列計數、整理排版（B1-26）；產生順序規則簡單可預期（位置由上而下）並畫出順序號 |
| 語意規則寫太多會讓人覺得「怎麼接不上」 | 每個拒絕都有白話原因；只硬擋一定錯的（§1b），其餘用 ⚠；嚴格模式是選項 |
