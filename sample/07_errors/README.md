# 07_errors（四個專案）

故意寫錯的程式，**不會建置成功**。組譯器分階段檢查，所以錯誤依出現的階段拆成四個專案：先看到上一階段的錯，修掉後才會看到下一階段的。
每個錯誤旁的註解標了預期的錯誤碼。

| 專案 | 階段 | 預期的碼 |
|---|---|---|
| `07a_errors_directives` | 讀檔：include、`.org`、重複標籤 | E104、E105、E106 |
| `07b_errors_instructions` | 單一指令：未知指令、運算元、MOV／ALU／CSR／分支／Peri 規則 | E101 E102 E103 E201 E202 E203 E204 E205 E206 E208 E307 |
| `07c_errors_flow` | 控制流、Cascade、DeviceMap、事件 | E301 E304 E309 E315 |
| `07d_errors_procedures` | 呼叫圖 | E305 |

## 試試看
1. 開啟任一專案：邊欄出現紅色圖示、紅色波浪線；問題面板列出全部錯誤；**F8**（或點問題）逐個跳轉。
2. 懸停每個波浪線，訊息說明原因，很多還附修法（例如 `WRITE_BUF` 會提示「v31 改名 `WRITE_SP`，來源是 scratchpad」）。
3. 命令列 `asmc --explain E202`：標題、v31 名稱 `E_MOV_REGION_OR_RANGE`、怎麼修。
4. 一次修一個，觀察問題數即時減少；`07b` 全部修完後再開 `07c`。
5. 有錯誤時 F5（除錯）會被拒絕並說明「有錯誤的程式不能除錯」。
6. 這四個專案的大綱與補全仍可使用（盡力而為的索引不依賴組譯成功）。

## 為什麼不放在同一個檔案
組譯器遇到讀檔階段的錯誤就不再往下，否則會產生一堆由前一個錯誤引起的假錯誤。
