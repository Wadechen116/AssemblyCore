# 自動除錯

寫組合語言或拼積木時難免出現小錯：拼錯字、數字超出範圍、忘了結尾的跳躍……**自動除錯**一個按鈕把它們找出來、修好，再用模擬器把修好的程式跑一遍，告訴你還有什麼問題。

**Debug → Auto Debug**（`Ctrl+Shift+D`，工具列也有按鈕）會打開「自動除錯」面板並立刻執行。

## 兩個按鈕

| 按鈕 | 做什麼 |
|---|---|
| **找出並修復**（Find and fix） | 找出問題，**修復有把握的部分**，再執行修復後的程式找出剩下的問題。 |
| **只看不改**（Look only） | 一樣的分析，**不修改任何東西**：列出「可修復」的項目與執行時發現的問題。想先看看它打算改什麼，就按這個。 |

「每次建置成功後自動檢查」勾起來，每次建置成功就會自動做一次「只看不改」。

## 修改是怎麼進行的

1. 反覆「建置 → 讀組譯器的診斷 → 對**只有一種最可能修法**的診斷做修改 → 再建置」，最多 6 輪，直到建置乾淨或沒有進展。
2. **文字程式**：整批修改是**一個復原步驟**，在編輯器按一次 `Ctrl+Z` 全部還原。
3. **積木程式**：生成的 `.asm` 是唯讀的，所以修改做在**積木本身**（改對應積木的欄位、或在 domain 的程式碼結尾加一個 `jump` 積木），同樣是**一個復原步驟**。積木的欄位找不到對應的字時（例如那個字不是任何積木的欄位），該項標為「無法在積木中修復」，留給你手動改。
4. 沒有把握的一律**不改**：兩個候選一樣接近、差太多、或要靠你判斷的，原樣留著，列在清單裡並附上組譯器的修法建議。

**「已修復（請確認）」**（琥珀色）表示這項修復是**很可能正確的猜測，不是確定**：值是它挑的（0、中性值）、範圍被移動、位址被截斷，或標籤改名。請看一眼是不是你要的；不是的話改掉那個值就好。

清單的每一列都可以點：跳到出問題的積木（積木程式）或那一行（文字程式）。

## 會自動修復的

| 診斷 | 修法 |
|---|---|
| E101 未知的指令／指示詞 | 換成最接近且唯一的詞（`MVO` → `MOV`） |
| E103 未定義的符號 | 換成最接近且唯一的已定義符號或區域（`LIMT` → `LIMIT`） |
| E205 未知的分支條件 | 換成最接近且唯一的條件（`PERI_RESULT_VALD` → `PERI_RESULT_VALID`） |
| E301 未定義的分支目標 | 換成同一個 domain 裡最接近且唯一的標籤（`strat` → `start`） |
| E201 數字超出範圍 | 移到最近的合法值（service id `0` → `1`；移位量 `12` → `8`） |
| E201 暫存區範圍超出尾端 | 往前滑到剛好放得下（`MAIN_SCRATCHPAD[30..33]` → `[28..31]`，長度不變）——**這不能保證語意是你要的**，請看一下 |
| E201 CSR 位址超過 12 位元 | 截成 12 位元（`0x1230` → `0x230`）——同上，請確認沒有和別的 CSR 撞位址 |
| E202 常數直接 MOV 進 `ALU_OPA`／`ALU_OPB` | 改成經過一對空的暫存區位元組（從暫存區上端往下找沒被用到的）：`MOV CONST → 暫存區`，再 `MOV 暫存區 → ALU_OPx`（spec v31 5.1）。2 位元組的常數才修；1 位元組的需要你決定。**只用於文字程式。** |
| E204 `EXEC_CSR WRITE_BUF` | 改名 `WRITE_SP`（v31 改名）——**資料來源也改了，請確認 `ptr` 指向暫存區** |
| E303 程式碼可能跑出結尾 | 在結尾補一個跳回該 domain 第一個標籤的 `JMP` |
| E203 未知的 ALU 運算 | 換成最接近且唯一的運算（`ADDD` → `ADD`） |
| E104 標籤定義了兩次 | 第二個改名（`s` → `s_2`）。指向 `s` 的跳躍仍然去第一個——**請確認** |
| E105 指令出現在任何 `.main`／`.peri` 之前 | 在它前面補 `.main`（`EXEC_XFER`／`EXEC_PUB` 補 `.peri`）——**請確認** |
| W501 `ALU_OPA`／`ALU_OPB` 沒載入 | **只有這個運算元在整個 domain 裡從來沒被載入過**才補（有的路徑載入了，哪個值屬於另一條路徑要你決定，不動）。補在 ALU 運算前面：優先用同一段直線程式裡**最後寫進暫存區的 2 位元組值**（且沒給另一個運算元用過）；沒有就用**該運算的中性值**（ADD／SUB／OR／XOR／CMP 補 `0`，AND 補 `0xFFFF`，MUL 補 `1`），經過暫存區（v31）。標籤會搬到補進去的第一行（跳到它的人也會跑到補進去的載入）——**請確認值** |
| W502 暫存區位元組被讀卻從沒被寫 | **domain 裡完全沒有任何指令寫那幾個位元組**才補：在讀之前先設成 `0`——**請確認值** |
| W504 ALU 結果被下一個運算蓋掉 | 兩個 ALU 之間是**一條直線**（中間沒有標籤、分支、跳躍、呼叫）才補：先把 `ALU_OUT` 存進一對空的暫存區位元組——**請確認要從那裡用** |
| W410 LOGIC 運算帶 `signed`／`unsigned` | 拿掉（只用於文字程式） |
| W517 發佈長度和 `.service` 約定不同 | 把 `len=` 改成約定的長度（只用於文字程式） |

## 修好之後：執行分析

修復後的程式會在**獨立的模擬器**裡全速跑一段（預設 20 萬週期，可以調），不影響你正在除錯的那一個。找的是：

| 發現 | 意思 |
|---|---|
| **Fault**（錯誤） | 某個序列器故障了，附故障碼與出錯的那一行 |
| **Result slot overrun**（錯誤） | Peri 在 Main 取走上一筆結果之前又發佈了，前一筆結果遺失 |
| **The commit never fits the blanking window**（錯誤） | `frame.wcet_pgl` 比垂直消隱視窗還長，`PGL_COMMIT_ELIGIBLE` 永遠不會成立 |
| **… is waiting in a loop**（警告） | 跑到結束時還在一個小迴圈（含條件分支）裡打轉，期間沒有任何進展（沒發佈、沒取結果、沒匯流排傳輸、沒事件）。列出它在等的條件。如果那個等待是設計好的（很長的 timer、等下一個畫面），把執行週期調大就好 |
| **I2C device … did not acknowledge**（警告） | 裝置沒回 ACK：環境檔裡沒有那個位址的裝置 |
| **Hardware event … never dispatched**（警告） | 事件被觸發了，但序列器從沒到達 `event_safe` 的 BR，向量沒跑 |
| **Results are published but Main never takes one**（警告） | Peri 一直發佈，Main 一筆都沒取 |
| **… instruction(s) never ran**（備註） | 這次執行沒走到的路徑（錯誤分支、一直沒來的 service）。是你預期的就不用管 |

每一列可以按 **「偵錯到這裡」**：偵錯工作階段從週期 0 全速跑到那個發現發生的週期然後停住，讓你直接檢查當時的狀態（需要先開始偵錯）。

## 它做不到的

- **邏輯錯誤**：程式「合法但不是你要的」（算錯、條件寫反、順序不對）它看不出來。它只修**有明確單一修法**的語法與範圍問題，和找出**執行起來顯然有問題**的現象。
- 資料流警告裡**有一部分**會修（見上表：W501／W502／W504，且只在確定不會蓋掉別條路徑的情況下）。其餘不自動修，因為要補什麼、放在哪要看你的意圖：`W501`／`W502` 在某些路徑有載入時、`W503` ALU 結果還沒產生就讀、`W506` 旗標分支前沒有 ALU 運算、`W505` 沒檢查 `PERI_RESULT_VALID` 就取結果、`W514` 位元組順序。它們會列在清單裡，附上組譯器的建議。
- 補進去的值（0、中性值）只是讓程式**有定義**，不保證是你要算的數。
- 積木程式裡「新增一行」的修復只支援結尾的 `jump`；其他需要加積木的修復（例如常數經過暫存區）不在積木裡做。
- 說明文字目前是英文；介面和按鈕是繁體中文。

## 例子

打開 `sample/14_main_peri_sim`，把 `frame.wcet_pgl` 調到 1000，按「只看不改」：會報出原因（WCET 比視窗長）、後果（結果槽 overrun）和症狀（Main 卡在 `window:` 那個迴圈）。

在文字程式裡故意寫 `MVO`、`LIMT`、`PERI_RESULT_VALD`、`strat`，按「找出並修復」：全部修好、補上結尾的 `JMP`，用 `Ctrl+Z` 一次還原。
